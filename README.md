# Polymarket → Discord Alerts

Watch a curated list of Polymarket traders and post every qualifying bet to Discord —
the amount, the side + odds, the market, the size, the wallet, and the trader's recent
PnL — auto-sorted into per-sport channels, with a cross-category whale feed.

> **spartachio just bet $109.92**
> **BUY** Yakult Brothers @ 30¢ · +234 · 3.34
> 🎯 Open market on Polymarket
> **Market** Dota 2: Yakult Brothers vs Vici Gaming — Game 1 Winner
> **Size** $109.92 (367 shares)  **PnL 7d** 🟢 +$64,722  **PnL 14d** 🟢 +$102,263
> **Wallet** spartachio — full record · `tx 7c20c71c`

## Features

- **Curated, *verified-profitable* wallets** — ranked by each trader's real profile PnL
  (the same number Polymarket's profile graph shows), not the unreliable leaderboard figure.
- **Per-sport channels** — each trade is routed to the right channel (Soccer, Esports,
  Crypto, Politics, Basketball, Baseball, …) using Polymarket's market tags.
- **🐳 Whale Alerts** — any bet ≥ $5,000 is also posted to a dedicated whale channel.
- **Filters** — BUYS only and a minimum bet size (default $100), both configurable.
- **Rich cards** — price in ¢ + American/decimal odds, size in $ and shares, and the
  trader's last-7-day / last-14-day PnL.
- **Reliable** — de-duplication, immediate state persistence, a global rate-limit queue,
  and a `tx` stamp on every card for traceability. Runs 24/7 on a tiny always-on host.

## How it works
Polymarket Data API ──> this bot (always-on) ──> Discord webhooks
/activity (trades) polls every ~20s one per sport channel
/user-pnl (PnL) filters + routes + a whale channel
Gamma /events (tags) de-dupes by tx

Polling the public, documented `/activity` endpoint is simpler and sturdier than the
WebSocket feed, and on an always-on host there is no per-run cost. ~20s latency is plenty
for "just bet" alerts.
## Quick start
**Prerequisites:** Node 20+, a Discord server you can add webhooks to.
### 1. Pick the wallets
Generate a watch-list from the leaderboard, ranked by *verified* 30-day PnL:
```bash
npm run pick-wallets -- --minVol=250000 --minPnl=10000 --limit=20
Flags: --minVol (activity floor), --minPnl (verified profit floor), --window
(1d|7d|30d|all), --limit, --orderBy (pnl|vol). This writes the wallets array
into wallets.json and preserves your channel config.

2. Create Discord webhooks
For each sport channel + the whale channel + a catch-all "other" channel:
Edit Channel → Integrations → Webhooks → New Webhook → Copy URL. No bot token needed —
the webhook's name/avatar is the sender.

3. Configure wallets.json
cp wallets.example.json wallets.json   # first time only
Fill in:

channels — a webhook per sport (keys: soccer, esports, crypto, politics,
basketball, baseball; add more by editing src/categories.js).
whaleWebhookUrl — the whale channel.
defaultWebhookUrl — the catch-all "other" channel (anything uncategorized lands here).
wallets — usually generated by pick-wallets; each entry is { address, name }.
4. Run
npm start
On first run it records a baseline per wallet and only alerts on trades that happen
after startup (it will not dump history).

⚠️ Webhooks are secrets — read before sharing this repo
wallets.json contains live Discord webhook URLs. Anyone who has a webhook URL can
post to that channel. This file is committed so the bot can deploy, which means:

Before sharing or forking this repo, replace every webhook in wallets.json
(and whaleWebhookUrl / defaultWebhookUrl) with your own, or scrub them:
# blank out all committed webhooks before sharing
sed -i -E 's#https://discord.com/api/webhooks/[0-9]+/[A-Za-z0-9_-]+#REPLACE_ME#g' wallets.json
If a webhook ever leaks, delete it in Discord (Channel → Integrations → Webhooks)
and create a new one — that instantly revokes the old URL.
Keep the repo private unless you've scrubbed/rotated the webhooks.
Configuration reference
wallets.json fields: pollIntervalMs, defaultWebhookUrl, whaleWebhookUrl,
channels (map of sport → webhook), wallets ([{ address, name }]).

Environment variables (all optional; they override the file / have safe defaults):

Variable	Default	Purpose
MIN_BET_USD	100	Minimum bet size to alert on (numbers only — no $)
WHALE_MIN_USD	5000	Whale-alert threshold
BUYS_ONLY	true	false to also alert on sells
POLL_INTERVAL_MS	20000	How often to poll each wallet
DEFAULT_WEBHOOK_URL	—	Overrides defaultWebhookUrl
WHALE_WEBHOOK_URL	—	Overrides whaleWebhookUrl
STATE_FILE	./.state.json	Where posted-trade state is persisted
POST_HISTORICAL_ON_START	false	true to post recent history on first run
Deploy (Railway)
This needs an always-on host (serverless platforms like Vercel sleep between requests
and won't work). Railway is the easiest:

Push this repo to GitHub, then New Project → Deploy from GitHub repo.
It auto-runs npm start. Ignore "no port detected" — this is a worker, not a web app.
Add a volume so state survives restarts: Variables → STATE_FILE=/data/state.json,
then Settings → Volumes → mount at /data.
Set filters as needed (MIN_BET_USD, WHALE_MIN_USD, …) in Variables.
Two rules to avoid duplicate alerts:

Settings → Deploy → Teardown = ON (kills old containers on redeploy).
Exactly one deployment of this repo. Two Railway projects/services — or a stray
npm start on your laptop — means two bots posting everything twice.
Maintenance
Refresh the roster: re-run npm run pick-wallets …, commit, push. Channels untouched.
Add a category: create a Discord channel + webhook, add it to channels in
wallets.json, and add a matching rule line to src/categories.js.
Tune filters: change MIN_BET_USD / WHALE_MIN_USD / BUYS_ONLY (env vars).
Troubleshooting
Duplicate cards → more than one bot is running. Check: a second Railway
project/service, a stray npm start locally, or a deploy overlap. Each card's tx
footer confirms a true dupe (same tx) vs two similar bets (different tx).
400 Bad Request {"embeds":["0"]} → an invalid embed, usually an image URL with a
space; image URLs are URL-encoded to prevent this.
429 rate limits → handled by a global send queue (~1.6 posts/sec) with retries;
splitting busy traders across channels also helps.
min bet $NaN → the MIN_BET_USD value must be a bare number (e.g. 100, not $100).
No alerts → expected to be quiet until a watched trader places a qualifying bet.
